# Prompt 01: KPI Definitions

## Input Variables
- `{VERTICAL_ID}`: e.g., "healthcare_saas", "fintech", "manufacturing_iot"
- `{VERTICAL_NAME}`: e.g., "Healthcare SaaS", "FinTech Platform", "Manufacturing IoT"
- `{INDUSTRY_DESCRIPTION}`: 2-3 sentences describing the industry, buyer persona, typical deployment
- `{TARGET_BUYER}`: e.g., "VP of Clinical Operations", "CFO", "Plant Manager"
- `{KEY_BUSINESS_OUTCOMES}`: 3-5 outcomes the buyer cares about (e.g., "patient throughput", "compliance rate")

## Prompt

```
You are a {INDUSTRY_DESCRIPTION} domain expert building a customer health
scoring model for a B2B Customer Success platform. Generate a complete
KPI definitions file for the "{VERTICAL_NAME}" vertical.

CONTEXT:
- Target buyer: {TARGET_BUYER}
- Key business outcomes: {KEY_BUSINESS_OUTCOMES}
- The health model must predict churn, identify expansion opportunities,
  and surface operational risks before they impact revenue.

ARCHITECTURE CONSTRAINTS:
- Exactly 5 pillars (P1-P5), each with 6-8 KPIs
- Total KPIs: 30-40
- Pillar weights (L2) must sum to 1.0
- KPI weights (L1) within each pillar must sum to 1.0
- At least one pillar must focus on revenue/growth (typically P5, weight >= 0.25)
- At least one pillar must focus on product adoption/usage (typically P1)
- At least one pillar must focus on operational health/support (typically P2 or P3)

PILLAR DESIGN GUIDELINES:
- P1: Should capture "time to value" and adoption velocity
- P2: Should capture operational reliability and engagement
- P3: Should capture core product/platform performance
- P4: Should capture partner/channel or relationship health
- P5: Should capture expansion signals and revenue trajectory (HIGHEST weight)

FOR EACH PILLAR, provide:
- name: Display name (2-4 words)
- description: One sentence
- weight_l2: Float (all 5 must sum to 1.0)
- saas_equivalent: Nearest SaaS CS concept for cross-vertical benchmarking
- kpi_count: Number of KPIs in this pillar

FOR EACH KPI, provide:
- name: Display name (3-6 words)
- description: One sentence with business context
- pillar: P1-P5
- unit: "percentage", "days", "hours", "count", "score", "ratio", etc.
- higher_is_better: true/false
- weight_l1: Float (within-pillar weights must sum to 1.0)
- frequency: "daily", "weekly", "monthly", "quarterly"
- target: {"operator": "<" or ">", "value": N}
- health_range: [low, high] — green zone
- risk_range: [low, high] — yellow zone
- critical_range: [low, high] — red zone
- Range consistency: health is best, critical is worst, risk is in between
- For higher_is_better KPIs: critical < risk < health
- For lower_is_better KPIs: health < risk < critical

ALSO INCLUDE:
- TOP_BUSINESS_PREDICTORS: Top 5 KPIs most correlated with renewal/expansion
  (with correlation coefficients 0.80-0.95)
- CRITICAL_KPIS: 1-3 KPIs where breach = immediate revenue risk
  (with threshold and dollar impact per unit change)

OUTPUT FORMAT:
Python file matching this exact structure:

```python

    "P1": { ... },
    ...
}

    "P1-KPI1": { ... },
    ...
}

TOP_BUSINESS_PREDICTORS = { ... }
```

3. The highest-weighted KPI in P5 should be the strongest churn/expansion predictor
4. Include at least 2 ML-derived predictive KPIs (e.g., churn probability, expansion probability)
